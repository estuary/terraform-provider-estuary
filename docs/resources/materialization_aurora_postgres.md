# estuary_materialization_aurora_postgres (Resource)

Materializes Estuary collections into tables of an Amazon Aurora for PostgreSQL database.

See the [Bindings](https://registry.terraform.io/providers/estuary/estuary/latest/docs/guides/bindings), [Backfills](https://registry.terraform.io/providers/estuary/estuary/latest/docs/guides/backfills) and [Secrets](https://registry.terraform.io/providers/estuary/estuary/latest/docs/guides/secrets) guides for how the provider manages them.

## Example Usage

```terraform
variable "postgres_password" {
  type      = string
  sensitive = true
}

variable "ssh_private_key" {
  type      = string
  sensitive = true
}

variable "dbt_api_key" {
  type      = string
  sensitive = true
}

# Password authentication with per-binding field selection and delta updates.
resource "estuary_materialization_aurora_postgres" "analytics" {
  name = "analytics"

  config = {
    address  = "analytics.cluster-123456789.us-east-1.rds.amazonaws.com:5432"
    user     = "flow_materialize"
    database = "analytics"
    schema   = "estuary"

    credentials = {
      auth_type = "UserPassword"
      password  = var.postgres_password
    }
  }

  bindings = [
    {
      source   = "acmeCo/mongodb/shop/users"
      resource = { table = "users" }
    },
    {
      source = "acmeCo/mongodb/shop/orders"
      resource = {
        table  = "orders"
        schema = "sales"
      }

      fields = {
        recommended = "1"
        exclude     = ["internal_notes"]
        group_by    = ["customer_id", "order_id"]
      }
    },
    {
      source     = "acmeCo/mongodb/shop/events"
      not_before = "2026-01-01T00:00:00Z"
      resource = {
        table         = "events"
        delta_updates = true
      }
    },
  ]
}

# IAM authentication following a capture, with hard deletes.
resource "estuary_materialization_aurora_postgres" "replica" {
  name = "aurora/replica"

  source = {
    capture            = "acmeCo/aurora/source-amazon-aurora-postgres"
    delta_updates      = false
    fields_recommended = "1"
  }

  target_naming = {
    strategy = "matchSourceStructure"
  }

  on_incompatible_schema_change = "disableBinding"

  config = {
    address     = "replica.cluster-123456789.us-east-1.rds.amazonaws.com:5432"
    user        = "flow_materialize"
    database    = "replica"
    hard_delete = true

    credentials = {
      auth_type    = "AWSIAM"
      aws_region   = "us-east-1"
      aws_role_arn = "arn:aws:iam::123456789012:role/estuary-materialize"
    }
  }

  bindings = [
    {
      source = "acmeCo/aurora/public/orders"
      resource = {
        table                       = "orders"
        schema                      = "public"
        additional_table_create_sql = "CREATE INDEX orders_customer_id ON public.orders (customer_id);"
      }

      fields = { recommended = "unlimited" }
    },
  ]
}

# SSH tunnel with a dbt Cloud job trigger.
resource "estuary_materialization_aurora_postgres" "private" {
  name = "warehouse"

  config = {
    address  = "warehouse.cluster-123456789.us-east-1.rds.amazonaws.com:5432"
    user     = "flow_materialize"
    database = "warehouse"

    credentials = {
      auth_type = "UserPassword"
      password  = var.postgres_password
    }

    network_tunnel = {
      ssh_forwarding = {
        ssh_endpoint = "ssh://ec2-user@ec2-123-4-567-89.compute-1.amazonaws.com:22"
        private_key  = var.ssh_private_key
      }
    }

    dbt_job_trigger = {
      access_url = "https://cloud.getdbt.com"
      account_id = "67890"
      job_id     = "12345"
      api_key    = var.dbt_api_key
      mode       = "skip"
      interval   = "1h"
    }

    advanced = {
      sslmode = "require"
    }
  }

  bindings = [
    {
      source   = "acmeCo/mongodb/shop/orders"
      resource = { table = "orders" }
      backfill = { trigger = 1 }
    },
  ]
}
```

Refreshes and deletions address it, so a provider tenant change replaces the materialization under the new tenant, with a plan warning, instead of managing whatever entry has its name there.

### Nested Schema for `bindings.resource`

Required:

- `table` (String) Table to materialize into. The connector creates it, unless it created it before. Changing it on an existing binding moves it to a new table, which the connector backfills from the start of the collection, leaving the old table in place.

Optional:

- `additional_table_create_sql` (String) SQL statements run in the same transaction that creates the table, such as a CREATE INDEX. They only run when the connector creates the table: a backfill truncates an existing table without running them, so run them yourself on it. Don't re-create the table in them.
- `delta_updates` (Boolean) Appends the changes of each transaction instead of merging them into one row per key. Defaults to false. Switching it from true to false requires a backfill: raise backfill.trigger, or the materialization's, in the same change, or the plan fails.
- `schema` (String) Schema of the table, overriding config.schema. Omitted, it keeps the live one, and a new binding gets the one target_naming names, as in the dashboard, or the endpoint default without target_naming. Changing it on an existing binding moves it to a new table, which the connector backfills from the start of the collection, leaving the old table in place.

### Nested Schema for `bindings.fields`

Required:

- `recommended` (String) Depth of the fields selected by default: '0' selects only the root document and the required fields, such as the collection key, '1' the top-level fields, '2' the second-level fields too, and so on, and 'unlimited' every field.
