# estuary_source_rds_postgres (Resource)

Captures tables of an Amazon RDS for PostgreSQL database into Estuary collections, through change data capture with PostgreSQL logical replication.

See the [Bindings](https://registry.terraform.io/providers/estuary/estuary/latest/docs/guides/bindings), [Backfills](https://registry.terraform.io/providers/estuary/estuary/latest/docs/guides/backfills) and [Secrets](https://registry.terraform.io/providers/estuary/estuary/latest/docs/guides/secrets) guides for how the provider manages them.

## Example Usage

```terraform
variable "postgres_password" {
  type      = string
  sensitive = true
}

variable "ssh_private_key" {
  type      = string
  sensitive = true
}

# Password authentication with automatic discovery.
resource "estuary_source_rds_postgres" "shop" {
  name = "rds"

  auto_discover = {
    add_new_bindings                = true
    evolve_incompatible_collections = true
  }

  config = {
    address      = "shop.123456789.us-east-1.rds.amazonaws.com:5432"
    user         = "flow_capture"
    database     = "shop"
    history_mode = false

    credentials = {
      auth_type = "UserPassword"
      password  = var.postgres_password
    }

    discovery_filters = {
      include_schemas = ["public"]
    }
  }

  bindings = [
    {
      resource = {
        namespace = "public"
        stream    = "users"
      }
    },
    {
      resource = {
        namespace = "public"
        stream    = "orders"
      }
      target = "acmeCo/shop/orders"
    },
  ]
}

# IAM authentication capturing every change event.
resource "estuary_source_rds_postgres" "events" {
  name = "rds/events"

  config = {
    address      = "events.123456789.us-east-1.rds.amazonaws.com:5432"
    user         = "flow_capture"
    database     = "events"
    history_mode = true

    credentials = {
      auth_type    = "AWSIAM"
      aws_region   = "us-east-1"
      aws_role_arn = "arn:aws:iam::123456789012:role/estuary-rds-capture"
    }
  }

  bindings = [
    {
      resource = {
        namespace = "public"
        stream    = "accounts"
        priority  = 10
      }
    },
    {
      resource = {
        namespace = "public"
        stream    = "audit_log"
      }
      backfill = {
        mode = "Only Changes"
      }
    },
  ]
}

# SSH tunnel with a dedicated publication and slot.
resource "estuary_source_rds_postgres" "private" {
  name = "rds/private"

  config = {
    address      = "private.123456789.us-east-1.rds.amazonaws.com:5432"
    user         = "flow_capture"
    database     = "shop"
    history_mode = false

    credentials = {
      auth_type = "UserPassword"
      password  = var.postgres_password
    }

    network_tunnel = {
      ssh_forwarding = {
        ssh_endpoint = "ssh://ec2-user@ec2-123-4-567-89.compute-1.amazonaws.com:22"
        private_key  = var.ssh_private_key
      }
    }

    advanced = {
      publication_name = "estuary_publication"
      slot_name        = "estuary_slot"
      sslmode          = "require"
      source_tag       = "rds-private"
    }
  }

  bindings = [
    {
      resource = {
        namespace = "public"
        stream    = "payments"
      }
    },
  ]
}
```

<a id="nestedatt--bindings--backfill"></a>
### Nested Schema for `bindings.backfill`

Optional:

- `mode` (String) How the table contents are backfilled. Leave it unset to let the connector choose: 'Normal' emits every change right away, 'Precise' holds back changes to rows the backfill hasn't reached yet, 'Only Changes' skips the backfill and only captures new changes, and 'Without Primary Key' backfills tables without a primary key. Changing it requires a backfill: in the same change, set or raise trigger, or set or raise the capture's, which backfills every enabled binding, or the plan fails.
- `strategy` (String) Overrides the backfill.strategy of the capture for this binding: 'incremental' or 'dataflowReset'. Changing it alone publishes nothing.
- `trigger` (Number) Set or raise it to backfill the binding: capture the whole resource again. A provider control Estuary never sees, not its backfill counter: each set or raise adds one to the live counter, or resets the collection with 'dataflowReset', leaving the counter as is. Setting it when the binding or the capture is added, or in the first apply after an import, backfills nothing. At least 1, can't be lowered, and can't be set or raised on a disabled binding.

Optional:

- `backfill_chunk_size` (Number) Number of rows fetched in a single backfill query. Defaults to 50000.
