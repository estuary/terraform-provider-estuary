# estuary_source_dynamodb (Resource)

Captures Amazon DynamoDB tables into Estuary collections, backfilling each table with parallel scans and reading its changes from DynamoDB Streams.

See the [Bindings](https://registry.terraform.io/providers/estuary/estuary/latest/docs/guides/bindings), [Backfills](https://registry.terraform.io/providers/estuary/estuary/latest/docs/guides/backfills) and [Secrets](https://registry.terraform.io/providers/estuary/estuary/latest/docs/guides/secrets) guides for how the provider manages them.

## Example Usage

```terraform
variable "aws_secret_access_key" {
  type      = string
  sensitive = true
}

# Access key authentication with automatic discovery.
resource "estuary_source_dynamodb" "shop" {
  name = "dynamodb"

  auto_discover = {
    add_new_bindings                = true
    evolve_incompatible_collections = true
  }

  config = {
    region = "us-east-1"

    credentials = {
      auth_type             = "AWSAccessKey"
      aws_access_key_id     = "AKIAXXXXXXXXXXXXXXXX"
      aws_secret_access_key = var.aws_secret_access_key
    }
  }

  bindings = [
    {
      resource = {
        table = "orders"
      }
    },
    {
      resource = {
        table = "customers"
      }
      target = "acmeCo/shop/customers"
    },
  ]
}

# IAM role authentication with a limited backfill read capacity.
resource "estuary_source_dynamodb" "events" {
  name = "dynamodb/events"

  config = {
    region = "eu-west-1"

    credentials = {
      auth_type    = "AWSIAM"
      aws_role_arn = "arn:aws:iam::123456789012:role/estuary-dynamodb"
      aws_region   = "eu-west-1"
    }
  }

  bindings = [
    {
      resource = {
        table          = "events"
        rcu_allocation = 1000
      }
    },
  ]
}

# DynamoDB-compatible endpoint, such as DynamoDB Local.
resource "estuary_source_dynamodb" "local" {
  name = "dynamodb/local"

  config = {
    region = "us-east-1"

    credentials = {
      auth_type             = "AWSAccessKey"
      aws_access_key_id     = "local"
      aws_secret_access_key = var.aws_secret_access_key
    }

    advanced = {
      endpoint          = "https://dynamodb.example.com"
      backfill_segments = 4
      scan_limit        = 500
      idle_backoff_max  = "1m"
    }
  }

  bindings = [
    {
      resource = {
        table = "orders"
      }
    },
  ]
}
```

<a id="nestedatt--config--advanced"></a>
### Nested Schema for `config.advanced`

Optional:

- `backfill_segments` (Number) Number of segments the backfill scan of each table is split into. Defaults to 100. Has no effect once the backfill of a table has started.
- `endpoint` (String) AWS endpoint URI to connect to, for both DynamoDB and DynamoDB Streams. Use it to capture from a DynamoDB-compatible API that AWS doesn't provide. The plan rejects credentials in it, such as user:password@ or a password or token option, as state and logs would hold them in plain text. Credentials found in the live value show as ***.
- `idle_backoff_max` (String) Maximum wait between polls of an open stream shard whose reads keep returning no records, as a whole number with one unit ('ms', 's', 'm' or 'h', e.g., '30s') between '1s' and '10m'. Defaults to '1s'. Higher values reduce billed DynamoDB Streams requests on idle shards, but delay the capture of new records by up to this wait.
- `scan_limit` (Number) Maximum number of items each backfill scan request evaluates. By default, it's unlimited, except for tables whose read capacity, from rcu_allocation or else provisioned, is 100 or less, which use 100.



<a id="nestedatt--auto_discover"></a>
### Nested Schema for `auto_discover`

Optional:

- `add_new_bindings` (Boolean) Adds a binding for each resource discovery finds in the source that isn't declared, when the capture is created and on each later discovery. Terraform doesn't manage those bindings; declare a binding to manage it.
- `evolve_incompatible_collections` (Boolean) Automatically updates the target collections when the source schema changes in a way they can't accept.


<a id="nestedatt--backfill"></a>
### Nested Schema for `backfill`

Optional:

- `strategy` (String) Default backfill strategy of the bindings: 'incremental' (default) captures again into the existing collection, 'dataflowReset' resets the collection, backfilling its materializations and truncating their tables. Changing it alone publishes nothing.
- `trigger` (Number) Raise it to backfill every enabled binding of the capture, including those Terraform doesn't manage. A provider control Estuary never sees, not its backfill counter: each raise adds one to each binding's live counter, or resets its collection with 'dataflowReset', leaving its counter as is. Starts at 1 and only goes up.
