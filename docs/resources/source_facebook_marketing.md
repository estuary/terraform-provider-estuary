# estuary_source_facebook_marketing (Resource)

Captures Facebook Marketing resources, such as campaigns, ads and their insights, into Estuary collections.

See the [Bindings](https://registry.terraform.io/providers/estuary/estuary/latest/docs/guides/bindings), [Backfills](https://registry.terraform.io/providers/estuary/estuary/latest/docs/guides/backfills) and [Secrets](https://registry.terraform.io/providers/estuary/estuary/latest/docs/guides/secrets) guides for how the provider manages them.

## Example Usage

```terraform
variable "meta_app_id" {
  type      = string
  sensitive = true
}

variable "meta_app_secret" {
  type      = string
  sensitive = true
}

variable "meta_access_token" {
  type      = string
  sensitive = true
}

# Two ad accounts with the access token of your own Meta app and a custom insights report.
resource "estuary_source_facebook_marketing" "ads" {
  name = "ads"

  auto_discover = {
    add_new_bindings                = true
    evolve_incompatible_collections = true
  }

  config = {
    account_ids              = "123456789,987654321"
    start_date               = "2024-01-01T00:00:00Z"
    insights_lookback_window = 28

    custom_insights = [
      {
        name              = "spend_by_age"
        level             = "campaign"
        fields            = "account_id,campaign_id,impressions,clicks,spend"
        breakdowns        = "age,gender"
        action_breakdowns = "action_type"
      },
    ]

    credentials = {
      credentials_title = "OAuth Credentials"
      client_id         = var.meta_app_id
      client_secret     = var.meta_app_secret
      access_token      = var.meta_access_token
    }
  }

  bindings = [
    {
      resource = {
        name     = "campaigns"
        interval = "PT1H"
      }
    },
    {
      resource = {
        name     = "spend_by_age"
        interval = "PT1H"
      }
      target = "acmeCo/ads/spend-by-age"
    },
  ]
}

# A capture created through the dashboard login, imported with its secrets left out.
resource "estuary_source_facebook_marketing" "imported" {
  name = "ads/imported"

  config = {
    account_ids = "123456789"
    start_date  = "2024-01-01T00:00:00Z"

    credentials = {
      credentials_title = "OAuth Credentials"
    }
  }

  bindings = []
}
```

### Required

- `backfill` (Attributes) Backfill control of the whole capture. (see [below for nested schema](#nestedatt--backfill))
- `data_plane` (String) Data plane the capture runs in (e.g., ops/dp/public/example-data-plane), defaulting to the provider data_plane when the capture is created. Estuary can't move a live capture, so setting another data plane than it runs in fails the plan.
- `image` (String) Connector image, defaulting to ghcr.io/estuary/source-facebook-marketing-native:v1. Only the tag can change, e.g. ghcr.io/estuary/source-facebook-marketing-native:dev.
- `keep_unmanaged_bindings` (Boolean) Keeps the live bindings the configuration doesn't declare, such as those Estuary or the dashboard adds, untouched. False manages every binding, removing undeclared ones, and conflicts with auto_discover. Defaults to true. A provider control Estuary never sees.
- `shards` (Dynamic) Shard settings of the capture, with Estuary keys such as logLevel and disable.

### Read-Only

- `catalog_name` (String) Catalog name the capture was created or imported under, with the tenant and connector name. Refreshes and deletions address it, so a provider tenant change replaces the capture under the new tenant, with a plan warning, instead of managing whatever entry has its name there.

### Nested Schema for `bindings.backfill`

Optional:

- `strategy` (String) Overrides the backfill.strategy of the capture for this binding: 'incremental' or 'dataflowReset'. Changing it alone publishes nothing.
- `trigger` (Number) Set or raise it to backfill the binding: capture the whole resource again. A provider control Estuary never sees, not its backfill counter: each set or raise adds one to the live counter, or resets the collection with 'dataflowReset', leaving the counter as is.
