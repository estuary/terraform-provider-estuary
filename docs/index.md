# Estuary Provider

Manage [Estuary](https://estuary.dev) captures (sources) and materializations (destinations) as code. Each resource manages a capture or a materialization of one Estuary connector, and each capture resource has a data source of the same name listing every live binding of a capture.

New to the provider? Start with the [Getting Started](https://registry.terraform.io/providers/estuary/estuary/latest/docs/guides/getting-started) guide.

## Prerequisites

| Requirement | Version |
|---|---|
| Terraform | >= 1.11 |
| [`flowctl`](https://docs.estuary.dev/concepts/flowctl/) | Latest, on `PATH` or set through `flowctl_path` |
| Estuary account | [Sign up for free](https://dashboard.estuary.dev) |

The provider runs `flowctl` to reach Estuary, so it must be installed where Terraform runs.

## Example Usage

```terraform
terraform {
  required_version = ">= 1.11"

  required_providers {
    estuary = {
      source  = "estuary/estuary"
      version = "~> 0.1"
    }
  }
}

# Provider for the acmeCo/ tenant, authenticated by FLOW_AUTH_TOKEN.
provider "estuary" {
  tenant = "acmeCo/"
}
```

## Authentication

The provider authenticates with an Estuary refresh token, from the dashboard under Admin > [CLI-API](https://dashboard.estuary.dev/admin/api). Set it in `FLOW_AUTH_TOKEN` rather than in the configuration. Access tokens also work but expire, so use a refresh token in CI/CD.

| Attribute | Environment Variable |
|---|---|
| `token` | `FLOW_AUTH_TOKEN` |
| `tenant` | `ESTUARY_TENANT` |
| `data_plane` | `ESTUARY_DATA_PLANE` |
| `backend` | `ESTUARY_BACKEND` |

An attribute set in the provider block overrides its environment variable. Every attribute must be known at plan time: a value only known after apply, such as another resource's attribute, fails the plan.

## Schema

### Optional

- `backend` (String) How the provider reaches Estuary. Defaults to flowctl, currently the only backend. Can also be set through ESTUARY_BACKEND.
- `data_plane` (String) Data plane that new captures and materializations are created in, and that capture discovery runs on (e.g., ops/dp/public/example-data-plane). Required for BYOC or a non-default public data plane. Defaults to the first data plane of your storage mapping. Existing entries keep their data plane. Can also be set through ESTUARY_DATA_PLANE.
- `flowctl_path` (String) Path to the flowctl binary. Defaults to flowctl on PATH.
- `tenant` (String) Prefix added to every capture and materialization name that doesn't already start with it, such as acmeCo/ or acmeCo/dev/. A missing trailing slash is added. Collection names you write yourself aren't prefixed. Can also be set through ESTUARY_TENANT.
- `token` (String, Sensitive) Estuary refresh token, from the dashboard under Admin > CLI-API. Access tokens also work but expire, so use a refresh token in CI/CD. Can also be set through FLOW_AUTH_TOKEN, and one of them is required.
