# estuary_source_google_play (Resource)

Captures the Google Play reports of a developer account, such as installs, crashes and reviews, into Estuary collections.

See the [Bindings](https://registry.terraform.io/providers/estuary/estuary/latest/docs/guides/bindings), [Backfills](https://registry.terraform.io/providers/estuary/estuary/latest/docs/guides/backfills) and [Secrets](https://registry.terraform.io/providers/estuary/estuary/latest/docs/guides/secrets) guides for how the provider manages them.

## Example Usage

```terraform
variable "google_play_service_account" {
  type      = string
  sensitive = true
}

# The installs and reviews reports of a developer account.
resource "estuary_source_google_play" "apps" {
  name = "apps"

  config = {
    bucket     = "pubsite_prod_1234567890123456789"
    start_date = "2024-01-01T00:00:00Z"

    credentials = {
      credentials_title = "Google Service Account"
      service_account   = var.google_play_service_account
    }
  }

  bindings = [
    {
      resource = {
        name     = "installs"
        interval = "PT1H"
      }
    },
    {
      resource = {
        name     = "reviews"
        interval = "PT1H"
      }
      target = "acmeCo/apps/play-reviews"
    },
  ]
}
```

### Required

- `name` (String) Catalog name of the capture (e.g., shop). The provider adds the tenant in front and the connector name at the end, unless they're already there. Changing the resulting catalog name, through name or the provider tenant, replaces the capture.

### Optional

- `auto_discover` (Attributes) Periodically checks the source for new resources and schema changes. (see [below for nested schema](#nestedatt--auto_discover))
- `backfill` (Attributes) Backfill control of the whole capture. (see [below for nested schema](#nestedatt--backfill))
- `data_plane` (String) Data plane the capture runs in (e.g., ops/dp/public/example-data-plane), defaulting to the provider data_plane when the capture is created. Estuary can't move a live capture, so setting another data plane than it runs in fails the plan.
- `image` (String) Connector image, defaulting to ghcr.io/estuary/source-google-play:v1. Only the tag can change, e.g. ghcr.io/estuary/source-google-play:dev.
- `keep_unmanaged_bindings` (Boolean) Keeps the live bindings the configuration doesn't declare, such as those Estuary or the dashboard adds, untouched. False manages every binding, removing undeclared ones, and conflicts with auto_discover. Defaults to true. A provider control Estuary never sees.
- `shards` (Dynamic) Shard settings of the capture, with Estuary keys such as logLevel and disable.

### Read-Only

- `catalog_name` (String) Catalog name the capture was created or imported under, with the tenant and connector name. Refreshes and deletions address it, so a provider tenant change replaces the capture under the new tenant, with a plan warning, instead of managing whatever entry has its name there.

### Nested Schema for `bindings.backfill`

Optional:

- `strategy` (String) Overrides the backfill.strategy of the capture for this binding: 'incremental' or 'dataflowReset'. Changing it alone publishes nothing.
- `trigger` (Number) Set or raise it to backfill the binding: capture the whole resource again. A provider control Estuary never sees, not its backfill counter: each set or raise adds one to the live counter, or resets the collection with 'dataflowReset', leaving the counter as is. Setting it on a binding Estuary doesn't have yet, when the capture is created, or in the first apply after an import, backfills nothing, while setting it on an existing binding Terraform takes over backfills it. At least 1, can't be lowered, and can't be set or raised on a disabled binding.

### Nested Schema for `backfill`

Optional:
